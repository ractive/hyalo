## HIGH

### A-1 alias fix in frontmatter loses the alias and can stay broken

    mkdir -p sub other
    printf -- '---\naliases: [AKA]\n---\n# Head\n' > sub/Target.md
    printf '# Twin\n' > other/Target.md
    printf -- '---\na: "[[AKA]]"\n---\nbody [[AKA]]\n' > s.md
    hyalo links fix --apply --dir . --no-hints --format text
    cat s.md

Actual: `a: "[[Target]]"`, body `[[sub/Target|AKA]]`. HYALO006 afterwards: ambiguous frontmatter wikilink `Target` matches 2 candidates. `summary.links.broken` 2 -> 1.

Expected: `a: "[[sub/Target|AKA]]"`, as the body gets.

Details:
- Plan text says `"AKA" -> "sub/Target.md"` under the heading "alias kept as display text". What is written is neither.
- JSON `alias_fix_plans[].emitted_target` is null for the LF frontmatter link.
- The same frontmatter link in a CRLF file takes the other path: `emitted_target: "sub/Target|AKA"`, and writes `"[[sub/Target|AKA]]"`. LF and CRLF give different bytes.
- Without a twin the result still resolves, but the alias text is gone.
- Accuracy note: a bare `[[AKA]]` is already broken by default (DEC-308), so this is a fix that fails and is reported as applied, not a working link newly broken.

Contract: DEC-308 ("plans that exact rewrite", `[[Note|alias]]`) and the byte-truthful `emitted_target` rule (BUG-17).

### A-2 alias fix demotes a fragment to display text

    printf -- '---\naliases: [AKA]\n---\n# Head\n## Second\n' > sub/Target.md
    printf 'b [[AKA#Second]]\n' > s.md
    hyalo links fix --apply --dir . --no-hints --format text

Actual: `[[sub/Target|AKA#Second]]`, read back as `target sub/Target`, `fragment null`, `label "AKA#Second"`.

Expected: `[[sub/Target#Second|AKA]]`. The anchor is lost and the display text is wrong. It also hides a broken anchor: `[[AKA#Nope]]` becomes `[[sub/Target|AKA#Nope]]`.

Only the bare form is hit. `[[AKA#Second|shown]]`, `![[AKA#Second]]` and the frontmatter form keep the fragment. Plain `--apply`, no fuzzy opt-in.

### A-3 unescaped pipe in a table cell

    printf -- '---\ntitle: Beta Doc\naliases: [Bee]\n---\n# Beta Doc\n' > sub/beta.md
    printf '# T\n\n| Name | Note |\n|------|------|\n| Beta Doc | x |\n| [[Bee]] | y |\n' > t.md
    hyalo links auto --apply --dir . --no-hints --format text
    hyalo links fix  --apply --dir . --no-hints --format text

Actual: `| [[beta|Beta Doc]] | x |` and `| [[sub/beta|Bee]] | y |`.

Expected: `[[beta\|Beta Doc]]`. Rows now have three cells under GFM table rules. hyalo already knows the escaped form: `mv` and `links fix` preserve an existing `[[x\|y]]`. Neither `lint` nor `find` notices the damage, because hyalo's link scanner still reads the link.

Not checked in Obsidian itself; this rests on the GFM rule and on hyalo's own `\|` handling.

### A-4 mv breaks links it counted as backlinks

    printf '# H\n' > note.md
    printf -- '---\nr: "[[./note]]"\n---\n[[note?]] [[note?x=1]] [[note]]\n' > s.md
    hyalo backlinks note.md --dir . --no-hints --format json   # total 4
    hyalo mv note.md --to moved.md --dir . --no-hints --format json
    hyalo find --broken-links --dir . --no-hints --format json --fields links

Actual: `total_links_updated: 1`, nothing in `skipped_ambiguous` or `frontmatter_links_skipped`. Three links now broken: `./note`, `note?`, `note?x=1`.

Expected: all 4 rewritten, or each one listed. `mv` lists what it cannot attribute rather than guessing.

mvforms.py over 50 forms, 4 layouts: these fail in every layout: `[[note?]]`, `[[note?x=1]]`, `[[note?#H]]`, `[[note?|a]]`, `[[note.md?]]`, `[[my%20note?]]`, frontmatter `[[note?]]`. Frontmatter `[[./note]]` fails from the vault root, though body `[[./note]]` is rewritten. Everything else resolved before and after.

Contract: DEC-374, "the same target spellings give one answer in every command"; the `[[note?]]` class named in the brief, here in the non-ambiguous path.

### A-5 backlinks under a drifted index

    mkdir a; printf '# T\n' > a/t.md; printf '[[t]]\n' > a/s1.md
    hyalo create-index --dir . --no-hints --format json; sleep 2.2
    rm a/s1.md; printf '[[t]]\n' > a/s2.md
    hyalo backlinks a/t.md --dir . --no-hints --format json          # a/s2.md
    hyalo backlinks a/t.md --index --dir . --no-hints --format json  # a/s1.md, deleted; stderr 0 bytes
    hyalo find --file a/t.md --fields backlinks --index ...          # a/s1.md; stderr 0 bytes
    hyalo find --glob 'a/t*' --fields backlinks --index ...          # a/s2.md, with the note

Expected: repair in memory with the `-q`-proof note, as the snapshot contract says of a READ command. Instead the result names a file that does not exist, exit 0, no warning. An in-place edit that removes the link has the same effect. `find --file` does repair the file's own properties and body; only the graph is stale.

Contract: `create-index --help` SNAPSHOT CONTRACT; DEC-339.

### A-6 `[links] frontmatter = false` ignored under --index

    printf '[links]\nfrontmatter = false\n' > .hyalo.toml
    printf -- '---\nother: "[[target]]"\n---\nbody\n' > src.md; printf '# T\n' > target.md
    hyalo create-index --no-hints --format json
    hyalo backlinks target.md --no-hints --format json          # total 0
    hyalo backlinks target.md --index --no-hints --format json  # total 1
    hyalo summary --no-hints --format json         # links.total 0, orphans 2
    hyalo summary --index --no-hints --format json # links.total 1, orphans 0

Also differs: `find --orphan`, `find --dead-end`, `find --fields backlinks`. A rebuild does not help, so this is not staleness. `find --fields links` agrees on both paths; the graph edges do not. Only vaults with the non-default setting are affected.

Contract: DEC-269 narrowing; `--index` parity.

### A-9 init replaces a malformed config

    printf '# my config\ndir = "docs"\n[schema.types.note]\nrequired = ["title"\n' > .hyalo.toml
    hyalo init --dir docs --no-hints --format text; echo $?

Actual: exit 0, file is now `dir = "docs"`, no backup. One typo costs schema, views and lint rules. Bare `init` skips the same file, and `init --profile` refuses it. Every other command refuses an unusable config.

This is deliberate in crates/hyalo-cli/src/commands/init.rs:567 and a test pins the warning text, so it may be a design call. It still conflicts with iteration 173's "no hyalo generator may ever destroy hand-written content".

### A-10 dry-run drift exits 1

DEC-307 and .claude/CLAUDE.md: drift is "never in the exit code", and exit 1 always renders the error envelope. Their `--help` documents the non-zero exit as a CI signal, so code and help agree and the contract does not. Either amend DEC-307 or change the commands.

## What worked well

- Disk and index agree on all four external corpora across 16 command shapes each, except the known `summary` keys (DEC-377).
- Incremental `create-index` matched `--force` on 5 queries after an edit, a new note and a directory move. A no-op rerun gave `written: false`. Stale reads repaired in memory and named the drift.
- Link truth: on GitHub Docs a path oracle found 0 false-broken and 0 false-resolved links across 17,047 links. On the Hub every broken link whose stem exists is flagged ambiguous, and all 22 sampled ambiguous links were true.
  On kepano no broken link has a matching stem. On MDN no file exists at the path of any of 25 sampled broken links; several of those are the known `_colon_`/`_star_` slugs (DEC-320).
- `links fix --apply` on a Hub copy: alias rewrites in Obsidian's form, relative links stay extension-less, and counts agree afterwards.
- 430 hinted and seed commands crawled on the own KB, Hub, kepano and GitHub Docs: no hint errored (`lint` exits 1 only on real error findings), and no `writes: false` hint was a write. 89 section-hit hints and line ranges all returned the right section.
- 23 deliberately wrong invocations gave correct exit codes and clear errors; `--allow-outside-vault` is well signposted; broken pipe returns 141.
- Search grammar, facets, `~N`, phrases and did-you-mean for stems that do not end in `s` behaved as documented.
