# Dogfood v0.23.0 — realistic workflows after the architecture repairs

Tested on 12 September 2026 at `36745a4604d8c398303cee61027c7151c778996a`.
The reviewed release executable was copied to a fixed path before exploration;
all counted checks used `/tmp/hyalo-review-20260912/bin/hyalo`.
The local Cargo installation was refreshed to the same executable. Other PATH
installations were initially stale and were not used as product evidence.

reproductions: [[reviews/codebase-review-2026-09-12]]. Previous dogfood baseline:

## Reverified behavior

| Workflow | Result |
| --- | --- |
| Phrase/Boolean search | `"red blue" OR green` returned exactly the phrase note and the green note, on disk and with an index |
| Negative phrase | `rust -"memory safety"` retained `rust memory allocation`, on disk and with an index |
| Indexed metadata mutation | Setting `status=reviewed` was immediately visible through indexed filtering |
| Task output preflight | `task toggle ... --all --count` failed before changing bytes |
| jq preflight | A syntactically invalid jq filter on append failed before changing bytes |
| Empty files-from | Find emitted an empty filename stream; set changed nothing; both warned that nothing was examined |
| Move and backlinks | A normal move rewrote incoming links and retained the correct indexed backlink |
| Derived-state parity | All returned file objects matched exactly between disk and index after set, task toggle, and move |
| Literal task examples | Native task fixing and a full lint fix left indented, fenced, and HTML-comment examples byte-identical |
| Scoped apply hint | Replaying the actual hint from a files-from lint preview fixed only the chosen file; the unselected file was byte-identical |
| Malformed batch member | Bulk set changed the valid note, skipped the malformed note, and reported the skip rather than silently claiming full coverage |
| External symlink | Named read, indexed regex/section search, set, move, init, and deinit refused the tested escape; external sentinels survived unchanged |
| Symlink-source move | Moving an alias onto its referent was refused with both entries preserved |
| Case collision | Applied batch move of `a/Foo.md` and `b/foo.md` to one directory was refused on the tested case-insensitive filesystem; both source bodies survived |

These are selected counterchecks against the last review, not closure of every
historical finding. No deterministic late-I/O failure was injected in this
manual round; the existing automated suite covers additional failure paths.

## UX observations

- `new --dry-run` on `alias/new.md`, where `alias` points to a directory inside
  the vault, previews success. Apply then exits 2 with `new file parent is a
  symlink: alias`. There is no write or escape; preview and apply should share
  this predictable refusal. Evidence: `new-alias-preview.json` and
  `new-alias-apply.json`.
- The fixed-artifact discipline mattered: more than one stale Hyalo executable
  was installed, and different shell PATH ordering selected different versions.
  Always record the binary's full path and revision when reproducing a defect.
- The own-KB summary and saved-view hints were usable, and the tested apply hint
  retained its exact resolved file. This is a practical improvement over the
  previous scope-widening hints.
- GitHub Docs' dry-run diagnostics were visible on stderr. VS Code Docs also
  emitted a date-value suggestion; that is advisory content, not a demonstrated
  incorrect mutation.
- Marker-based generator previews would benefit from a compact textual diff:
  a `changed` boolean and action name do not expose which surrounding prose a
  faulty splice will remove. This would aid review but does not substitute for
  fixing F1.
