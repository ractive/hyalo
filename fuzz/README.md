# hyalo fuzz targets

`cargo-fuzz` targets for the four parser surfaces that take attacker-controlled
bytes: a vault file's frontmatter, a vault file's body (scanner), a link
label/target, and a MessagePack snapshot index. These are the systematic
complement to the one-off proof-of-concept inputs that drove the SEC-1/2/3
hardening (frontmatter YAML-bomb defenses, snapshot entry/edge caps, path
validation) — see `reviews/adversarial-review-2026-08-23.md` and
`decision-log.md` for the incidents that motivated those checks.

**Not wired into CI**, by project preference (see `.claude/CLAUDE.md` /
`decision-log.md`): fuzzing and Miri are run manually as part of a security
review, alongside `cargo miri test -p hyalo-core`. This crate is excluded
from the parent workspace (`[workspace]` table in `fuzz/Cargo.toml`) so
`cargo build/test/clippy --workspace` at the repo root never touches it.

## Targets

| Target | Exercises | Entry point |
|---|---|---|
| `frontmatter_splice` | YAML frontmatter parse + the minimal-diff splice write path | `hyalo_core::frontmatter::{read_frontmatter, write_frontmatter}` |
| `scanner` | The streaming line/state-machine scanner (frontmatter delimiters, fences, BOM, line caps) | `hyalo_core::scanner::scan_slice_multi` |
| `link_parser` | `[[wikilink]]` / `[label](target)` extraction and zone-overlap logic | `hyalo_core::links::{extract_links_from_text, inert_link_zones, overlaps_zone}` |
| `snapshot_loader` | The MessagePack snapshot-index loader, including its SEC-1/2/3 caps | `hyalo_core::index::SnapshotIndex::load` |

## Prerequisites

```sh
rustup toolchain install nightly   # cargo-fuzz requires nightly (libFuzzer sanitizer support)
cargo install cargo-fuzz --locked
```

## Running

From the `fuzz/` directory (each target reads/writes `corpus/<target>/` by
default, which is gitignored — the tracked, curated seeds live in
`seeds/<target>/` and are not mutated by fuzzing runs):

```sh
cd fuzz

# Short smoke run (a few seconds), useful after touching parser code:
cargo +nightly fuzz run frontmatter_splice -- -max_total_time=15 seeds/frontmatter_splice

# A real fuzzing session — runs until stopped (Ctrl-C), growing corpus/<target>/
# and seeding from both the auto-grown corpus and the tracked seeds:
cargo +nightly fuzz run scanner corpus/scanner seeds/scanner

# All four targets, one after another, capped:
for t in frontmatter_splice scanner link_parser snapshot_loader; do
    cargo +nightly fuzz run "$t" -- -max_total_time=60 "seeds/$t"
done
```

A crash writes a minimized reproducer to `fuzz/artifacts/<target>/` (also
gitignored). Reproduce and debug it directly:

```sh
cargo +nightly fuzz run <target> artifacts/<target>/crash-<hash>
```

To build every target without running (part of PR self-review, not CI):

```sh
cargo +nightly fuzz build
```

## Seed corpus

`seeds/<target>/` holds a small, intentional set of inputs, not an
auto-grown corpus:

- `frontmatter_splice/`, `scanner/` — real files from `hyalo-knowledgebase/`
  (`decision-log.md`, an iteration file) plus hand-written edge cases: empty
  file, minimal frontmatter, an unterminated `---` block, a fenced code
  block.
- `link_parser/` — wikilink and Markdown-link substrings extracted from the
  same knowledgebase files, plus an unterminated `[[` and a mixed
  link-in-backticks line.
- `snapshot_loader/` — a real `.hyalo-index` snapshot generated by
  `hyalo create-index` against a small two-file vault.

Regenerate the snapshot seed after a `SnapshotData`/`SnapshotHeader` schema
change:

```sh
mkdir -p /tmp/seed-vault && cp ../hyalo-knowledgebase/decision-log.md /tmp/seed-vault/
../target/release/hyalo --dir /tmp/seed-vault create-index
cp /tmp/seed-vault/.hyalo-index seeds/snapshot_loader/seed-real-index.msgpack
```

## What this does not cover

- Byte-for-byte MessagePack fuzzing of every internal snapshot type — only
  the outer `SnapshotData` shape reachable via `SnapshotIndex::load`.
- The CLI argument parser (`clap`) or filesystem-path traversal logic
  (`discovery.rs`) — those are covered by the unit/e2e suites and the M-2
  Windows-gated tests instead (iter-224 T-4), not fuzzing.
- Throughput/performance regressions — see `xtask bench-scale` (iter-224
  T-6) for the scale gate; fuzzing here is about crashes and panics, not
  speed.
